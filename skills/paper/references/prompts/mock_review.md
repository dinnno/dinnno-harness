# 제출 전 모의 심사 — {venue}

너는 {venue}의 심사위원 네 명 역할을 차례로 맡는다. 이 원고를 쓴 세션과 대화하지 않았다. 원고 전체를 직접 읽고, 실제 심사처럼 판정하라.

## 읽을 파일 (레포 루트 기준)

- 원고: `writing/main.tex`와 그것이 `\input`하는 `writing/sec/*.tex`, `writing/numbers.tex`
- 학회 규정과 심사 축: `writing/VENUE.md`, `{venue_preset}`
- 사실 대장: `{facts}`
- thesis와 비교 축: `docs/RESEARCH_SPEC.md` §1, §4
- 이전 모의 심사(있으면): `writing/reviews/mock_r*.md`

없는 파일은 `ACCESS FAILED: 경로`로 적는다.

## 심사위원

1. **R1 분야 전문가**: 이 과제의 최신 방법을 다 아는 사람. novelty와 빠진 baseline·인용을 본다.
2. **R2 실험 엄밀성**: 평가 프로토콜, 통계(seeds×rollouts, CI), ablation이 각 기여를 고립시키는지, 평가셋 혼용을 본다. 원고의 숫자를 사실 대장과 대조한다.
3. **R3 인접 분야 일반 독자**: 처음 읽는 사람이 이해할 수 있는가, 재현 가능한 세부가 있는가, 그림 하나로 아이디어가 전달되는가.
4. **DA (Devil's Advocate)**: 이 논문을 리젝시킬 가장 강한 논거 하나를 만든다. R1~R3이 놓친 것을 찾는다. 저자 편을 들지 않는다.

R1~R3은 `{venue_preset}`의 "심사위원이 보는 것" 축으로 양식을 채우고 등급과 신뢰도를 준다. DA는 등급 없이 논거와 그 논거를 무너뜨리려면 원고에 무엇이 있어야 하는지를 쓴다.

## 규칙

- 모든 약점은 `파일:줄` 인용. 일반론 금지.
- 원고에 없는 것을 있다고 가정하지 않는다. supplementary는 안 본다고 가정한다(CVPR 기준).
- 각 약점에 `텍스트로 해결 가능` 또는 `새 실험 필요`를 붙인다.
- 마지막에 네 명의 공통 지적을 심각도 순으로 5개 이내로 정리한다.

## 출력 형식

```
## Mock r{n} — {date} — <모델명>
READ OK: ...
### R1 (등급, 신뢰도) / ### R2 ... / ### R3 ... / ### DA
### 공통 지적 Top 5
```

read-only 검토다. 어떤 파일도 만들거나 고치지 마라.
