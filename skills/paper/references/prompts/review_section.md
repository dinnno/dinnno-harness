# 섹션 적대 검토 — {sec} ({venue})

너는 {venue}의 회의적인 심사위원이다. 이 원고를 쓴 세션과 대화하지 않았다. 아래 파일을 직접 읽고 이 섹션을 검토하라. 질문은 "어떻게 다듬을까"가 아니라 "이 섹션 때문에 왜 리젝되는가"다.

## 읽을 파일 (레포 루트 기준)

- 검토 대상: `writing/sec/{sec_file}`
- 수치 매크로 정의: `writing/numbers.tex`, 매크로의 원천 목록: `writing/numbers.yaml`
- 사실 대장(원고가 써도 되는 사실과 강도): `{facts}`
- 저자의 의도 메모: `writing/notes/{sec}.md`
- 연구의 thesis와 비교 축: `docs/RESEARCH_SPEC.md` §1, §4
- 학회 규정: `writing/VENUE.md`
- 이전 검토 라운드(있으면): `writing/reviews/{sec}.md`
- 맥락용 다른 섹션(있으면): `writing/sec/` 아래 나머지 파일

없는 파일은 `ACCESS FAILED: 경로`로 적고 계속한다.

## 축 (축마다 격추를 시도하고, 결함이 없으면 `no finding`과 근거 한 줄)

1. 주장과 근거: 이 섹션의 주장마다 사실 대장 항목이나 원고의 표·그림이 받쳐 주는가. 강도가 "탐색"이나 "단일 seed"인 사실을 확정처럼 썼는가. 매크로를 거치지 않은 숫자가 있는가.
2. 기여와 novelty: 리뷰어가 "이미 알려진 것", "예측 가능한 개선", "naive baseline에 덧댄 것"으로 읽을 문장이 있는가.
3. 논리 흐름: 문단마다 메시지가 하나이고 첫 문장이 그것을 말하는가. 역개요(문단 첫 문장만 이어 읽기)가 섹션의 목적에 맞게 이어지는가. 정의 전에 쓰인 용어나 섹션 사이에 바뀌는 용어가 있는가.
4. 실험과 평가(실험 섹션이 아니어도, 이 섹션이 약속한 실험이 원고에 있는가): baseline 공정성, 빠진 ablation, seeds×rollouts, 평가셋 혼용.
5. 학회 규정: 익명성 위반, 금지 링크, 분량 위험.
6. 메모와의 일치: 저자 메모의 의도와 다르게 쓰였거나 메모에 있는데 빠진 핵심이 있는가.

## 심각도

- `CRITICAL` = 이대로면 리젝 사유가 되는 결함(근거 없는 핵심 주장, 익명성 위반, 기여가 성립하지 않음).
- `HARD` = 심사위원이 거의 확실히 지적해 점수를 깎을 결함.
- `SOFT` = 다듬으면 좋아지는 것.

차단의 기준은 하나다: "이 문장 때문에 점수가 내려가는가". 취향 차이는 SOFT다. HARD가 많다고 좋은 검토가 아니다.

## 근거 규칙

모든 지적은 `파일:줄`을 인용하고, 문제 문장을 짧게 옮긴다. 일반론("더 많은 실험이 필요하다") 대신 이 원고의 구체 문장과 수치를 따진다.

## 출력 형식

```
## Round {round} — {date} — <모델명>
READ OK: <읽은 파일 목록>
Verdict: REWRITE | FIX FIRST (CRITICAL a, HARD b) | READY
### CRITICAL
- [제목] `파일:줄` "인용" — 왜 리젝 사유인가 — 최소 수정 한 줄
### HARD
...
### SOFT
...
### 축별 no finding
...
### 저자에게 묻는 질문 (최대 3개)
```

read-only 검토다. 어떤 파일도 만들거나 고치지 마라.
